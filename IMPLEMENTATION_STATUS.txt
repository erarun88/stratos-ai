KEY DESIGN DECISIONS
═════════════════════════════════════════════════════════════════════════════════

  ✓ ADR-001: Supervisor-Specialist Pattern
    → Why: Clear concerns, parallel execution, independent testing
  
  ✓ ADR-002: Standardized AgentResponse
    → Why: Enables composition, quality propagation, future phases
  
  ✓ ADR-003: Separate Planner & Executor
    → Why: Different concerns, supports approval, easier debugging
  
  ✓ ADR-004: Abstract Base Agent Class
    → Why: Enforces consistency, type safety, prevents mistakes
  
  ✓ ADR-005: Heuristic Agent Selection (now)
    → Why: Fast, cheap. LLM-based upgrade path in Phase 3
  
  ✓ ADR-006: Parallel Task Execution
    → Why: 3x latency reduction for complex requests
  
  ✓ ADR-007: Backward Compatibility
    → Why: No customer impact, phased rollout possible
  
  ✓ ADR-008: Supervisor as Pure Orchestrator
    → Why: Simplicity, extensibility, clear roles
  
  ✓ ADR-009: Tool Manager as Separate Component
    → Why: Reusable across agents, centralized management
  
  ✓ ADR-010: Citations as First-Class Objects
    → Why: Structured provenance, verifiable, type-safe

  See: ARCHITECTURAL_DECISIONS.md for full rationale
